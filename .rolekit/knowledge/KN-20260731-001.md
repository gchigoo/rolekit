# Core 宿主无关，CLI 为唯一通用表面，各宿主薄适配

## Context

RoleKit 需要在 Pi、Codex、Cursor 混用的环境工作。`讨论.md` 提案假设 Codex 主控，但既有资产（role_agent 扩展、veritack、deep-research）全在 Pi 侧；sdk-first 备份则把 Pi 钉为唯一控制平面并因此搁置。owner 日常混用多宿主，任何单宿主绑定都会造成返工。

## Decision

Core（Task Contract / Result Envelope / 状态机 / prompt 编译）不依赖任何宿主；`rolekit` CLI 是唯一通用表面；各宿主只提供薄 Skill / 规则文件入口，教会宿主驱动 CLI；工作流语义全部住 Core，不进 Skill。执行器第一版为 PiRpcExecutor。

## Consequences

- 不锁定运行时，执行器可替换（pi / codex-subagent / script / remote）
- MCP 降级为后置包装层，只包同一个 CLI / Runner
- 每新增宿主需维护一份薄适配，但不复制流程逻辑
- Skill 承载流程逻辑即违反本决策

## Alternatives Considered

- Codex 主控（讨论.md 原案）：生态文档对齐，但与资产分布错位，日常主力不确定时空转
- Pi 唯一控制平面（sdk-first 案）：已因过重、钉死 Pi 0.80.10、日常 TUI 摩擦大而搁置
