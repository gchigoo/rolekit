# 全库 TypeScript（常规工具链），契约用 TypeBox 单一来源

## Context

曾考虑统一 mjs 以求零构建轻量。核实后：Node 22.18+ 默认开启 type stripping，24 LTS 已 stable，`node file.ts` 可直跑（erasable 语法内）；mjs 的零构建优势不再成立。既有资产（role_agent 扩展、veritack src、deep-research）全为 TS，deep-research 已使用 TypeBox。

## Decision

全库 TypeScript，常规工具链：开发期 node 直跑，CI 跑 `tsc --noEmit`，发布 npm 时才 bundle。契约 schema 用 TypeBox 单一来源，同时产出运行时校验、静态类型和 JSON Schema 导出。

## Consequences

- 与全部既有资产零语言切换，迁移复用无摩擦
- 不存在"为 Pi 特设 ts adapter"的语言分裂
- 需保持 tsconfig 与 Node 直跑行为一致（module: nodenext 等）；深度依赖 enum 等非 erasable 语法时需构建步骤兜底

## Alternatives Considered

- mjs + JSDoc + `tsc --checkJs`：工具链没省，人体工学更差
- core 用 mjs、adapter 用 ts 混合：语言分裂，最差
