# 配置格式分层：YAML 人写，JSON/JSONL 机器产物，不引入 TOML

## Context

RoleKit 同时存在人写配置（RoleProfile、policies、项目配置）和机器产物（编译后 task、result、事件流）。遗产（CodeStable / superpowers）全部是 markdown + YAML frontmatter，迁移工具的目标格式选择直接影响映射成本。

## Decision

人写文件用 YAML（`profiles/*.yaml`、`policies/gates.yaml`、`rolekit.yaml`）；机器产物一律 JSON / JSONL（编译后 task、`result.json`、`events.jsonl`、runtime manifest）。每类文件冻结一份 JSON Schema（由 TypeBox 导出，见 ADR 004），YAML 解析后走同一 schema 校验。不引入 TOML。

## Consequences

- 迁移工具源目标格式同源（YAML frontmatter → YAML），转换最少
- 机器产物无歧义、diff 稳定、校验零成本
- 需在 CLI 层统一加载校验入口，防止绕过 schema 手改产物

## Alternatives Considered

- 全 JSON：人写配置无注释，可读性差
- TOML 人写：深嵌套（scope / acceptance 树）表达差，且形成三格式并存
